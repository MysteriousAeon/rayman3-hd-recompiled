# Stage 2C: prepare first; human authorization required for each real launch

No unattended startup is approved. Do not put the human blocks into automation.
No Codex on CachyOS is needed. Do not repeat old builds/finalization/probes.

Copy `r3hd-stage2c-attended-startup.zip` and its `.sha256` to Downloads, compare
the ZIP hash with the committed startup report, then run this **preparation only**:

```bash
set -euo pipefail
cd "$HOME/Downloads"
sha256sum -c r3hd-stage2c-attended-startup.zip.sha256
RUNNER="$HOME/Downloads/r3hd-stage2c-attended-startup-01"
test ! -e "$RUNNER" && test ! -L "$RUNNER"
mkdir "$RUNNER"
python3 -B -m zipfile -e r3hd-stage2c-attended-startup.zip "$RUNNER"
(cd "$RUNNER" && sha256sum -c SHA256SUMS)
df -B1 --output=avail,target "$HOME/Projects"
python3 -B "$RUNNER/startup.py" prepare
```

Expected marker: R3HD_STAGE2C_STARTUP_PREPARED, NO EXECUTABLE ENTRY. Requires
>=1,000,000,000 available bytes on the existing filesystem; two independent copies
of ~105MB program files, private homes and small logs. No alternative storage,
packages, privileges, containers/images, source/game builds or downloads required.
Reads the existing native package/LGPL archive/ABI receipts and both supplemental
evidence pairs. All hashes must match. No copyrighted game data is needed or copied.

Creates only `~/Projects/R3HD-baseline-noble-2c-startup-01`, with independent reject
and wayland installations. Existing installations, previous probe installation,
saves, settings, Mods, translations, images and evidence stay untouched. Any name
collision, symlink, changed/missing artifact or low space: STOP; preserve everything.

**STOP HERE unless the maintainer personally authorizes an attended launch.** The
following are separately authorized human actions, not an unattended-safe recipe.
Remain present. A window/dialog or focus change may occur even in the rejection
case; there is no visible fallback executed by the script. Each command requires
a real terminal, --human-present and a mode-specific typed authorization phrase.
Wrong/absent authorization refuses before any launch. Never pipe an answer.

First human-authorized check, independent of game data:

```bash
(cd "$RUNNER" && sha256sum -c SHA256SUMS)
python3 -B "$RUNNER/startup.py" human --mode reject --human-present
```

When prompted, the person may authorize by typing `AUTHORIZE ATTENDED REJECT`.
This requests the deliberately nonexistent video backend r3hd_stage2c_reject.
It is an expected negative startup test: exact SDL initialization error plus a
natural exit1, no successful video backend/app-host marker, no runtime/guest marker.
Wrapper success marker: R3HD_STAGE2C_ATTENDED_REJECT PASS. Actual executable entry
is established only by that native result; it does not establish normal startup.
Timeout15s, then TERM only its own process group,3s grace then KILL; interruption,
forced termination, crash or surviving group means FAIL, even if a marker appeared.

Only after that PASS, the maintainer may separately authorize the next visible
Wayland presentation/data-guard test. It is optional; stop after reject if desired.

```bash
(cd "$RUNNER" && sha256sum -c SHA256SUMS)
python3 -B "$RUNNER/startup.py" human --mode wayland --human-present
```

The person must type `AUTHORIZE ATTENDED WAYLAND`. This explicitly authorizes a
windowed test in their current Wayland session. The private HOME/XDG directories
are fresh; only the owned existing Wayland socket is passed as an absolute display
path. No X11 fallback, fullscreen, global input injection or desktop automation.
D-Bus addresses point to nonexistent sockets in the private home; no inherited
R3HD/injection/audio/session variables are passed. The executable's existing
presentation/Vulkan path is exercised; there is no renderer or SDK change.

Game-data root deliberately points to a **nonexistent** private path. It must stay
nonexistent. Do not create it, copy data into it or point it at a working installation.
The source path checks it after presentation setup but before Runtime construction,
so no XEX or game/save/profile is loaded. The person may need to dismiss only this
test's missing-data error dialog. No keyboard/mouse action is generated by tools.

Expected: SDL video driver wayland, M2 host_start, exact missing-data-path error,
natural exit1; wrapper R3HD_STAGE2C_ATTENDED_WAYLAND PASS. Timeout45s with the same
owned-group handling. A modal timeout is FAIL, not clean exit or permission to retry.
Renderer presentation success is inferred from reaching the later data guard with
the explicit xenos plugin; runtime renderer/command processor/gameplay are not tested.
An initialized-runtime/XEX/guest-launch marker is unexpected: STOP and report it.

After the chosen human checks (or after a failed attempt), collect once:

```bash
python3 -B "$RUNNER/startup.py" collect
TASK="$HOME/Projects/R3HD-baseline-noble-2c-startup-01"
(cd "$TASK" && sha256sum -c startup-private-evidence.zip.sha256)
```

Return only startup-private-evidence.zip and its sidecar privately. Collection
excludes installations, private HOME, user-data and cache. It preserves separate
loader logs, attempt/exit receipts, early stdout/runtime logs and per-mode results.
No result is a full gameplay/save/audio/input/distro/hardware compatibility claim.
Natural exit1 is an expected rejection, not a normal exit0 startup milestone.

Any failure: retain terminal output and collect if the startup root was created.
Never repeat an existing attempt, delete artifacts, change package/source hashes,
install tools, switch renderer or use --help/dummy/removed-DISPLAY as a fallback.
Do not run the installed Play/Settings launchers or start a gameplay campaign.
